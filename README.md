# ANTI-AIR — 台灣防空涵蓋分析工具

一個把「防空涵蓋」從**畫圓**提升到**可被檢驗的幾何與時間模型**的互動式視覺化工具。

## 這是什麼

輸入一組防空陣地（使用者自己放置，或載入示範想定），輸出：

- 指定高度切片下的**實際可攔截區域**（含地形遮蔽、雷達地平線、感測器俯仰限制）
- **縱深熱圖**：每一格被幾套系統、以幾次射擊機會涵蓋
- **垂直剖面圖**：沿任意一條線的側視圖，直接看出低空走廊在哪裡
- **接戰時間軸**：對一條給定航跡，誰在第幾秒偵獲、第幾秒能射、能射幾次

## 這不是什麼

- **不是**作戰規劃工具。所有數值都是公開推估值，帶有大到不能忽略的不確定度。
- **不宣稱**真實兵力部署。預設想定中的陣地位置皆為**假想示例**，僅供演示分層防空概念；
  使用者可自行放置陣地做「如果……會怎樣」的分析。
- 每一個參數都必須在 `data/sources.json` 留下來源，沒有來源的欄位一律標 `confidence: "low"`。

## 現況

**Phase 1–4 完成**：運動學包絡 + 雷達地平線 + 真實地形遮蔽 + 威脅條件化縱深熱圖 +
垂直剖面圖 + 威脅航跡與接戰時間軸（通道數、待發彈、飽和攻擊）。

時間軸輸出的是**射擊機會**，不是擊殺數。擊殺機率需要 Pk，而公開的 Pk 全是猜的 ——
捏一個出來只會把猜測包裝成戰損評估。理由詳見
[DESIGN.md](docs/DESIGN.md) 的 Phase 4 一節。

### 三個最快理解這個工具的操作

1. **把「地形」勾掉再勾回來**：台中平原的天弓三型對 100 m 目標，不算地形是一個完美的
   70 km 圓，算了地形之後 720 個方位有 376 個完全看不到。
2. **切到「縱深」圖層，然後只換威脅**：同一組陣地、同一個高度，攻擊機（RCS 5 m²）
   的缺口是 60%，巡弋飛彈（0.1 m²）是 77%，低可偵測性戰機（0.01 m²）是 95%。
3. **按「畫剖面」，拉一條穿過中央山脈的線**：低空走廊在側視圖上是一條看得見的縫。

### 圖層是互斥的

涵蓋／縱深／遮蔽一次只看一種。多層半透明疊圖會糊成一團，那是 3D 防空視覺化的通病。

## 快速理解專案的三個公式

```
可視性    MVA(φ, r) = h_site + r·tan(θmax(φ,r)) + r²/(2·k·Re)
偵測      R_det(RCS) = R_ref · (RCS / RCS_ref)^(1/4)
射擊機會  N = min( channels, floor(T_window / (t_flyout + t_assess)) )
```

第一式是整個引擎的基礎：算一次就同時得到**所有高度切片**與**雷達地平線**。
理由與推導見 DESIGN.md §3。
